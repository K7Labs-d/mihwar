# MIHWAR — Master Product Blueprint

الخريطة الأم لمنصة «محور»

Marketplace لتأجير المعدات الثقيلة — مرجع المنتج والمعمارية وترتيب البناء

حالة الوثيقة: مرجع تأسيسي للمنتج — تُحدّث عند كل Milestone رئيسية.

## 1. تعريف المنتج

«محور» سوق رقمي لتأجير المعدات الثقيلة يربط المستأجر بمالك/مؤجر المعدة. يتيح مسارين للحصول على المعدة: التصفح والاستئجار المباشر، أو نشر طلب احتياج واستقبال عروض من ملاك المعدات. يتوحد المساران لاحقًا في الحجز والدفع والتنفيذ والإكمال والتقييم. الدفع داخل المنصة، وتأخذ «محور» عمولة من المعاملة.

## 2. الأطراف الرئيسية

- المستأجر: يتصفح المعدات أو ينشر طلبًا، يستقبل العروض، يختار، يدفع ويتابع عملية التأجير.

- المؤجر / مالك المعدات: يُعتمد، يسجل معداته، يحدد السعر النهائي بالساعة و/أو اليوم، الموقع والتوفر وخيار المشغل، ويقدم معداته للطلبات المناسبة.

- الإدارة: تعتمد المؤجرين وتدير لاحقًا المعدات والمعاملات والمدفوعات والنزاعات والتشغيل.

- الحساب: المستخدم نفسه يمكن أن يكون مستأجرًا ومؤجرًا؛ لا يلزم حسابان منفصلان.

## 3. المساران الرئيسيان

### A — الاستئجار المباشر

تصفح المعدات → بحث/تصفية → تفاصيل المعدة → اختيار المدة وخيار المشغل → طلب مباشر → Booking

### B — نشر طلب واستقبال عروض

إنشاء Request → نشره → يظهر للمؤجرين المناسبين → المؤجر يختار معدة من معداته → Offer → مقارنة العروض → اختيار عرض → Booking

بعد Booking يتوحد المساران:

Booking → Payment → Commission / Lessor Payout → Execution → Completion → Review

## 6. الكيانات وقواعد العمل الأساسية

| الكيان | الدور |
| --- | --- |
| Equipment | كيان مستقل مملوك لمؤجر معتمد. يتضمن النوع/التصنيف، المواصفات، الموقع، الصور، سعر الساعة واليوم، مع/بدون مشغل، التوفر والحالة. |
| Request | احتياج ينشره المستأجر. يجب أن يتطور ليرتبط بتصنيف المعدة والموقع والتاريخ والمدة والكمية ومتطلب المشغل. |
| Offer | يربط Request + Lessor + Equipment. السعر الأساسي ليس تفاوضيًا عشوائيًا؛ يبنى على تسعير المعدة المسجل. |
| Booking | نقطة توحيد الاستئجار المباشر والعرض المقبول، وهو المرجع للدفع والتنفيذ. |
| Payment / Commission | تحصيل داخل محور، فصل عمولة المنصة عن مستحق المؤجر، مع قابلية الاسترداد والتسوية والضرائب لاحقًا. |
| Execution | دورة التشغيل بعد الحجز: تأكيد → بدء → متابعة → إتمام → إغلاق. |

## 7. حالة المشروع الحالية

مرحلة التشغيل المحدودة لاستقبال طلبات العملاء والرد عليها مدمجة في `main`، وموثقة في [ADMIN_REQUEST_INBOX.md](ADMIN_REQUEST_INBOX.md). تربط الإدارة والعميل بمحادثة محفوظة وصلاحية مستقلة، ولا تقدم بناء Offers أو Booking أو Payment، ولا تمثل اكتمال Admin Operations الشاملة أو نشرًا عامًا.

تحديث 2026-09-24: أُدمج أساس المؤجر وإدارة المعدات مع الحفاظ على دورة الطلبات والمحادثات وصلاحياتها. الاعتماد ينشئ ملف مؤجر دائمًا، والمعدات تُحفظ وتُسترجع مع ملكيتها وأسعارها وتوفرها. الترحيل الثالث يعالج طلبات اعتُمدت بالنسخة الأقدم بعد إنشاء الجداول، دون تغيير قراراتها أو الحسابات. التفاصيل في [LESSOR_EQUIPMENT_CORE.md](LESSOR_EQUIPMENT_CORE.md). كود السوق في فرع مستقل ولم يُدمج ضمن هذه المرحلة.

| الحالة | المحتوى |
| --- | --- |
| DONE | الحسابات والجلسات، Request الأساسية وصندوق الإدارة والمحادثات، تسجيل واعتماد المؤجر، Lessor Profile وEquipment وإدارة الأسعار والتوفر والأرشفة مع الحفظ الفعلي. |
| ADAPT | Request الحالي ليرتبط بتصنيف المعدة والتاريخ والمدة وخيار المشغل. تبقى أسماء broker الداخلية للتوافق مع البيانات والمسارات السابقة. |
| NEXT | سوق المعدات: مراجعة ودمج التصفح والبحث والتصفية وصفحة التفاصيل الموجودة في فرعها المستقل. |
| LATER | تطوير Request، Matching، Offers، Booking، Payment/Commission، Execution، Documents، Notifications، Reviews، Operations، Production. |

## 8. المرحلة التالية الرسمية — NEXT

Equipment Marketplace — سوق المعدات

الهدف: إتاحة تصفح معدات المؤجرين المعتمدين والبحث والتصفية وصفحة تفاصيل لكل معدة، بالاستفادة من Equipment الحالي ومن تنفيذ السوق المحفوظ في فرعه بعد مراجعته مع آخر نسخة من main.

## 10. قواعد هندسية حاكمة

- لا تُبنى ميزة قبل معرفة موقعها في الخريطة واعتمادياتها ومستخدمها وحالاتها ومعايير قبولها.

- لا إعادة كتابة للمشروع من الصفر ما دام الموجود قابلًا للتطوير.

- التغييرات المفاهيمية مثل broker → lessor تُنفذ تدريجيًا عند لمس الجزء، وليس بحملة Rename واسعة بلا قيمة فورية.

- لا Offers قبل Equipment؛ ولا Execution/Payment قبل Booking.

- لا بيانات وهمية مقدمة كحقيقية؛ استخدم Empty States.

- الملكية والصلاحيات والتحقق تُفرض على Backend، لا على الواجهة فقط.

- main يمثل النسخة المستقرة؛ الميزات الكبيرة تُنفذ في feature branches وتُدمج بعد الاختبار والمراجعة.

- تُحدّث هذه الوثيقة بعد كل Milestone رئيسية لتظل مرجع المشروع.
